一个字节
的一生

从手指压下去，到屏幕上亮起来。

十页 · 一次一次的拷贝

02 — 按下它

键盘不知道什么是「字符」

它只知道哪一个开关合上了。这个信息叫 scancode，一次三个字节：按下码、抬起码、外加一个用来区分多字节的 0xE0。

十六进制是 keyboard 那一侧的语言，不是你的。

03 — 中断

CPU 手里的事被打断了

IRQ 1 抬起来，内核的键盘驱动从键盘控制器里把 scancode 读走，翻成键码，塞进这个 tty 的输入队列。

此时它已经是一字节了，但还不在你的程序里。

04 — 行规程

谁来决定这个字节归谁

line discipline 站在中间。回显要不要、退格删不删、Ctrl-C 是不是信号 —— 都是它说了算，不是键盘，也不是你的程序。

这一步是纯逻辑，一次拷贝都没有。

05 — read

第一次交到你手上

read(0, buf, 1) 返回的那一克数据，是内核把环形缓冲区里的字节 copy_to_user 过来的。内核态 → 用户态，第一次拷贝。

清零一次、写入一次，两个地址空间。

06 — stdio

你的 printf 没打算马上写出去

它先抄进 FILE 那块 4 KB 的缓冲，攒着。遇到换行、缓冲满、或者你要读输入，才真正调一次 write。

第二次拷贝，抄进用户态自己的缓冲区。

07 — write

回到内核去

缓冲区满了，write(1, buf, n) 把这一段再 copy_from_user 回内核。第三次拷贝，方向和你 read 时相反。

到这里，内核已经拿到你要显示的字符串了。

08 — 终端

终端只认转义序列

它不认识「字」，只认识 ESC [ 开头的一串坐标与属性。谁把字符变成画，是这个软件的事，不是内核的事。

第四次拷贝：字符进字形缓存。

09 — 上屏

最后两跳

字形位图写进纹理 → 合成器把这一层贴到屏幕上。这两跳已经不是字符，是像素了，但它仍然是那块内存被搬来搬去。

第五、第六次。到这里它终于发光了。

10 — 结算

七次

一个字节，被完整搬了七次

  1. 1内核环形缓冲 → 你的 buf
  2. 2buf → stdio 的 4 KB
  3. 3stdio → 内核 pty
  4. 4pty → 终端的字符网格
  5. 5字符 → 字形位图
  6. 6位图 → GPU 纹理
  7. 7纹理 → 帧缓冲

所以「输入延迟」这个词，问的从来不是一次操作，是七次里的哪一次。
